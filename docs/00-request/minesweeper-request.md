# 需求 — dsh-minesweeper（DSH 扫雷插件）

> 本文件同时是 **v2.0 框架的验收测试用例**：在新开的「工程模式」会话里，
> 用户只发一句话（见 §1），Agent 应完整跑通七阶段 + SDD 并交付可玩的插件。

## 1. 用户原话

> 开发 dsh-minesweeper 扫雷插件

（一句话需求，无其他细节——正是用来检验 grill-me 澄清流程的输入。）

## 2. 已确认的需求基线（Q1–Q10 拷问结论）

| # | 决策点 | 结论 |
|---|--------|------|
| Q1 | 棋盘规模 | 10×10，雷数 10（起步规格；不做多难度） |
| Q2 | 交互 | 左键开格，右键插旗/取消旗 |
| Q3 | 计分/状态 | 顶部显示：剩余雷数（雷数-旗数）、计时器（秒，开格后起走）、重开按钮 |
| Q4 | 胜负 | 翻开所有非雷格=胜（停表+提示）；踩雷=负（标出踩中的雷+全部雷，停表） |
| Q5 | 首点安全 | 第一次点击必为安全格（雷在首次点击后生成，排除首点及其邻域） |
| Q6 | 数字显示 | 标准扫雷：开格显示相邻雷数（0 则连锁展开） |
| Q7 | UI 形态 | DSH 侧边栏卡片（参照 `dsh-personal-workbench` 的卡片/插槽模式），走 `--dsw-*` 主题 token，明暗模式自适应 |
| Q8 | 插件形态 | 纯 client 渲染 + 纯 client 状态（**无 host 状态、无持久化**）；host 侧仅最小入口（name/inject/apply 空实现） |
| Q9 | 开发/验证 | 临时实例 `DSH_HOME=$HOME/.dsh-dsh-minesweeper-test pnpm dsh web --port 3084` 开发验证；用户验收通过后才谈 3082 安装；开发期 link 安装 |
| Q10 | 范围边界 | 不含：多难度/计时挑战模式/统计持久化/移动端适配/联机；只交最小可玩版 |

## 3. 假设表（Agent 开工前可补充，须更新本表）

| 假设 | 依据 | 影响 |
|------|------|------|
| 棋局状态只存 client 内存，刷新即重置（不做持久化） | Q8 纯 client 约束 | 刷新丢棋局，可接受（Q10 非目标） |
| 右键在棋盘外点击 = 取消旗（无"同时开双邻格"的 chording） | 起步规格最小化（Q10） | 后续可加 |
| 主题跟随 DSH 设置，不自带独立配色 | Q7 | — |
| 冒烟测试覆盖：首点安全、胜负判定、计数一致性（纯逻辑层可单测） | 逻辑与 UI 分层（shared/ 纯函数） | 验收 A5 |

## 4. P0 需求（可测试验收标准）

| # | 验收项 | 验证方式（3084 临时实例） |
|---|--------|--------------------------|
| A1 | 插件在 3084 实例侧边栏可见、可打开棋盘卡片 | 浏览器操作 + 截图 |
| A2 | 左键开格/右键插旗，数字与连锁展开正确 | 手工对弈 3 局 |
| A3 | 首点安全：任意棋盘首点不踩雷（逻辑层 100 次随机断言） | `npm run check` + 冒烟测试 |
| A4 | 雷数/计时/重开正确：胜停表、负标雷、重开清零 | 手工 + 逻辑断言 |
| A5 | 纯 client：无 host 状态文件产生；client bundle 不含 node: 依赖 | `npm run check`（产物门禁） |
| A6 | 主题自适应：明/暗模式切换后棋盘可读 | 3084 切换主题目检 |
| A7 | `npm run check` 全绿（双端构建+门禁+typecheck+冒烟） | 命令输出留档 `docs/05-testing/` |

## 5. 约束与红线

1. 插件目录：`projects/dsh-minesweeper/`（本仓库内）；`init-project.sh --kind dsh-plugin` 起步。
2. SDD 强制：`docs/specs/001-minesweeper-core/` 三件套，spec 经用户确认前不实现。
3. **3082 红线**：未经用户验收，任何改动不得进入生产实例。
4. 版本从 0.1.0 起；交付物含 README/CHANGELOG/`docs/05-testing/` 证据。
5. 经验沉淀：踩坑写入 `docs/06-experience/`，并回写本框架 `docs/06-experience/`（框架侧复盘）。
